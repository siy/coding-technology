## The one that would have bitten again: publishing is not notifying

`--publish` makes a new version live and **emails nobody**. Leanpub's
`publish[email_readers]` defaults to `false` for books, and `publish-leanpub.sh` POSTs no
parameters, so its call is byte-for-byte Leanpub's documented "publish without notifying
readers" example. A moved `last_published_at` proves a version went live, never that a
reader was told.

PFD 2.4.0's appendices — which a reader had explicitly asked for — shipped silently, and
I reported it as published. Root cause: the script's own comment said "may email
readers", and I believed it instead of checking the API, then propagated the error into
the `/release` skill I had just rewritten.

Notifying is a separate, irreversible call:

```bash
curl -s -X POST "https://leanpub.com/<slug>/publish.json" \
  --data-urlencode "api_key=$LEANPUB_API_KEY" \
  --data-urlencode "publish[email_readers]=true" \
  --data-urlencode "publish[release_notes]=..."
```

Use `--data-urlencode`, not `-d` (spaces mangle). Confirm it fired: `job_status.json` must
report `job_type: EmailReadersJob`, not merely `{"success":true}`. Release notes go out in
the user's name, so **plain ASCII, no em-dashes**. Courses default the flag to *true*;
books do not. Recorded in `CLAUDE.md`, the release skill, the script, and memory.

## Book corrections, and how each was found

Every one came from software following the book literally, or from a reader pushing on a
case. **In each, the artifact that had been run against reality was the one that was
right.**

1. **Rule citations** — four documents ordered the selection rule four ways; the CH
   transcript cited "rule 3" for UNKNOWN-inert against *no list anywhere*. Rules are now
   cited by name; the UNKNOWN rule is stated in the book for the first time.
2. **Q2 bundled two scopes** — error budget (per service/path) with criticality (per
   operation), in the question list the entry gate's *decomposed* discipline exists to
   police. Fixed in AS 1.1.0 and PFD 2.4.1 (the series crosswalk claims both books ask the
   same nine).
3. **`separated` had three incompatible definitions** and the engine implemented a fourth.
   The graded blind runs used divergence + volume; both written statements were wrong.
   Implementing either would have retracted a HIT-graded published prediction. Staleness
   returned to the costs column.
4. **Q5's scope was narrower than its own values read** — `sharded` and `streaming` are
   conditioned on per-data-class load while Q5 elicited per-path only. The counterexample
   was inside the sentence stating the rule: "read-dominated at the HTTP tier and
   write-majority at the store, simultaneously".
5. **Predicate-over-a-set was misclassified** (PFD) — filed as the limit where design-out
   has nothing to bite on, while the section closes by condemning locking and then
   prescribing a locked counter. Rico Fritzsche's reply showed `where count < limit` in
   the write *is* the guarded transition. The real limit is a collision between
   derive-don't-store and the guarded transition.

## Conventions confirmed

- Publishing ≠ notifying (above). Verify `EmailReadersJob`, not just `success`.
- Comment drift is the recurring failure: **four wrong claims this session were comments,
  not code** — three asserting an absence that had since been filled, one asserting a
  capability that did not exist. Tests catch code drift; nothing catches prose.
- Releases: branch → PR → `gh pr merge --admin` → per-book tag → build → publish → verify
  → notify only if asked.
- Commits single-line conventional, no trailers, no attribution.
