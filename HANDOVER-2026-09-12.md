## Read this first: four things that will bite a successor

**1. A PR based on anything but `main` gets ZERO CI, and it looks like CI hasn't started yet.**
Both PR workflows filter `pull_request: branches: [main]`, which matches the *base*. Measured 2026-09-09:
#73 stacked on a feature branch had **0 check-runs** while #72 on `main` had **6**. A stacked PR shows an
**empty check list**, not a failure — indistinguishable from pending. This is in `CLAUDE.md` now. I made
this mistake and a dispatcher then spent a poll cycle waiting for checks that could never arrive.

**2. The repository ruleset changed, and `--admin` is no longer needed.**
Ruleset 9648960 was scoped `~ALL` → **`refs/heads/main`** and `required_approving_review_count` 1 → **0**;
`delete_branch_on_merge` is now **true**. `gh pr merge <n> --merge` works on its own. The old 1-approval
rule on a solo repo was what forced every merge through `--admin` — that was never a Claude Code
limitation. Feature-branch deletion no longer trips a bypass: 23 merged remotes were deleted with **zero**
"Bypassed rule violations" lines, where three the previous day each produced one.

**3. Netlify's Git integration is still building, and it CANNOT render this site.** #75 is blocked on it.
Two independent reasons, either fatal: the Netlify builder has no pandoc, and **its build image bakes in
pandoc 2.13**, old enough to reject the site's reader spec but new enough that an existence check sails
past it. The owner ruled to disconnect it (Netlify → site `jbct` → Build & deploy → stop builds) and keep
the GitHub Actions deploy, which uploads a prebuilt `dist` and now installs pinned pandoc. **As of the last
push the disconnect had not taken effect** — three netlify-app checks still appear on new commits.

**4. Three gates now fire on your own edits, and that is them working, not breaking.**
The blurb tripwire (#72), the `verified_against` guard (#76) and the `field_assignment` anchors (#76) each
redden when you touch what they cover. I tripped the last one myself rewording one sentence in
`aether.md`: it expects 2 attributed literals on that line and my wording produced 3. The fix is the prose,
not the count.

## Owner rulings — do not reopen

1. **Deploy: one path.** Disconnect Netlify's Git integration; the Actions deploy is canonical. Two builders
   racing on one commit can only agree or break.
2. **Ruleset: scoped to `main`, zero approvals, auto-delete on merge.**
3. **The version declaration splits in two.** `depends_on` (a coordinate, tracks Central mechanically, now
   **rc3**) and `verified_against` (what someone actually re-read, **per scope**: `jbct-book`=rc1,
   `jbct-tooling`=rc1, `aether-book`=rc3). Chosen over a one-off bump because rc4 is already on branch —
   a mechanism beats a ruling you re-make in weeks.
4. **npm is replaced, not pinned.** The owner's threat model, in their words: npm/node/npx run **locally**,
   so a package reaches everything on the machine; CI runs elsewhere and is not the concern. Three removed
   dependencies carried install-time hooks (`entities`, `esprima`, `markdown-it-anchor`). After #75
   `npm install` creates no `node_modules` and `dependencies` is `{}`.
5. **The `aether:*` wildcard is reworded, not filed.** It was false as written and substantively fine.
6. **Guard the slug mechanism, not the corpus.** A 1,414-line fixture would redden on every legitimate
   heading edit and train people to regenerate it reflexively.
