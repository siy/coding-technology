## Read this first: five things that will bite a successor

**1. A SQUASH-MERGED COMMIT IS NOT AN ANCESTOR, AND `--is-ancestor` REPORTS "UNMERGED" BY CONSTRUCTION.**
This is the correction of the session. I reported `2ae1723a1` (a runbook fix) as *done, committed,
unmerged, no PR* — in a proposal artifact, in two messages, and to the owner. **It was already in rc4**:
squash-merged as **PR #1007**, 2026-09-11T13:30:57Z, merge commit **`7fa26e2ca`**, an ancestor of rc4 tip
`18c80dabc`. Verified four independent ways after the CTO caught it: the `pulls` query, merge-commit
ancestry, content at the tip (`/api/v1/nodes/status` ×3, legacy `/api/nodes` ×0), and reproducing my own
false negative. **`git branch -a --contains` and `git branch --merged` inherit the same false negative —
a branch refused as unmerged may be fully merged by content, and that refusal is never a reason to reach
for `-D`.** Ask whether the *content* is present, or resolve the PR:
`gh api repos/<repo>/commits/<sha>/pulls`.

**And the tag half, which is the more general lesson.** The claim rode into a greppable `[verified:]`
namespace citing `git ls-remote` — an instrument that can establish a branch and its SHA and **cannot,
even in principle, establish "has no PR"**. The ancestry half was true and checked; the PR half was
neither, and inherited credibility from the half that was. **A tag must cite evidence that can bear every
claim it sits on, not just the one it was written for.**

**2. `--admin` is not needed, and the `/release` skill still says it is.** The ruleset is scoped to
`refs/heads/main` with zero required approvals; plain `gh pr merge --merge` works. The installed
`/release` skill still says "Branch protection requires admin" and **is not tracked in `ai-tools/`**, so
`check-drift.sh` cannot see it — five of ten installed skills sit outside the drift net.

**3. The retention rule is written but inert until #84 merges.** When it does, root holds `09-12` and
this file; **`HANDOVER-2026-09-09.md` moves to the private record in the same operation.** Not chained
onto an unmerged PR on purpose.

**4. Presence is not agreement.** I called the May–June conventions "already homed" because the private
authoring specs covered the same topics. They cover them *and contradict them* on one convention revoked
in June. When checking whether a rule is homed, check that the home **agrees**, not that it mentions the
subject.

**5. Merge order is free, but #84 alone is not sufficient.** #84 and #86 were made conflict-free by
aligning one region byte-identically (`merge-tree` CLEAN, verified both directions). **Merging #84 without
#86 leaves 9 pre-existing private-path lines**; #86 clears all of them.

## The Aether runbook skill — new work, decided but not approved

**Owner ruling 2026-09-15: the runbook-skill proposal and the manual-tester board item are decided
together.** It scopes **HOW** the decision is made, **not WHETHER to build** — the underlying decision is
still open, and a reader who takes it as approval has misread it. Proposal artifact is in the private
record; the CTO's Rev 2, still deferred, should now cover both as one.

**The finding that shrank the proposal: most of the guardrails already exist.**
- Per-operation authorization (#299): reads VIEWER, mutations OPERATOR, destructive ADMIN, **deny-by-default**
  for unlisted routes.
- API keys are **role-scoped**, `DEFAULT_ROLE = "VIEWER"` — least privilege already the default.
- CLI already has key create / list / revoke / rotate.
- Dry-run exists on the **declarative path only**, not as a management-API primitive.

So the skill binds its modes to existing roles rather than building new ones. **The real gap is credential
delivery, not authorization:** API keys arrive via the `AETHER_API_KEYS` **environment variable** — the
ambient-credential pattern the owner's `with-hcloud` mechanism exists to eliminate. Design points settled:
skill and runbooks bundle into the CLI; the credential wrapper must be an **executable on PATH**, not a
shell function, and **a refused capability must not produce the same message as an uninstalled tool**;
escalation impossible, de-escalation mandatory.

**Owed by the CTO, with its condition:** a `know:` commit recording the ruling. It cannot land while rc4 is
mid-merge-round; the condition is **after those PRs merge and rc4 is green at the post-merge tip, before
the candidate tag moves.** `know:` commits live in `pragmatica`, which this session does not edit — so a
read point taken there will not see this ruling until the CTO writes it.
