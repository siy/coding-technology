2. A **workflow materializes as code only when it has its own trigger**, distinct from any of its use cases' triggers (a schedule, an event, an entry point belonging to no single use case). Otherwise it stays **logical** (a grouping; callers invoke the constituent use cases directly).

## Durable decisions / principles (this session)

1. **Entity stance:** not anti-entity. Entities exist for **cross-field invariants enforced at persistence**; "process not entity" is the *default* design unit, not a ban. Entities reappear at the persistence boundary.
2. **Workflow:** logical by default; materializes only with its own trigger; materialized = use-case-like interface, never a use-case container.
3. **Trigger:** a process needs **≥1 trigger, unlimited count**; the **outcome** individuates the process.
4. **Cohesion = shared change driver / same reason to change, NOT lockstep co-change.** The seat reservation lifecycle is a state machine whose transitions are the four use cases.
5. **Design-out is not free** — it relocates cost (TTL/expiry management; the per-seat process is a serialization ceiling). Triangulated by Poltorak + Thor.
6. **Business-process hardening** — modeling as processes surfaces latent fragility pre-code (memory `project-business-process-hardening`).
7. **Diagrams = TikZ** (pure-LaTeX, no new dependency).
8. **Leanpub = upload mode** (own PDF/EPUB via `publish-leanpub.sh`); native-sync abandoned.
9. **Foreword:** not Loth; Hetland/Fritzsche or none; Poltorak → blurb.
10. **No em-dashes** in text the author sends/pastes as their own (memory `feedback-avoid-em-dashes-in-sends`).
