## Product-side (for the CTO to route)

1. **Reference docs contradict the code on entity deployability.** `guarantees.md` rows 26, 61
   ("not reachable from a deployed slice"), 63-64, 134 ("not a dependency of aether/node"), 140,
   142 and `known-limitations.md:105` still describe the pre-wiring world, while
   `aether/node/pom.xml:130-144` and the #596 arc shipped the opposite; `guarantees.md:139`
   (crash-gate row) is current. The repo's own `guarantees-corrections-needed.md` defers
   re-grounding to #496 — this delta makes that pass more urgent, since the docs now UNDER-claim.
2. **`DurableEntity` javadoc is stale against its own declaration.** The interface header still
   describes the "HA-only, in-memory first functional cut", and its qualifier usage example shows
   the two-type-parameter form `DurableEntity<String, OrderState>` while the interface takes
   three (`K, S, C extends Mutator<S>`). First thing a newcomer reads, and both halves mislead.
3. **Silent-inert timer trap (#351).** `scheduleTimer`/`cancelTimer` succeed and are durably
   logged; `EntityTimerDriver` exists but nothing in `aether/node` registers it, so a scheduled
   timer never fires on a deployed node — and the rich fire-semantics javadoc never says so. An
   author following the javadoc ships a workflow whose timeouts silently never happen. Book now
   carries the caveat; the javadoc should too until the driver lands.
4. **Retry-exhausted stream events are skipped, and the default dead-letter sink is in-memory.**
   After RETRY×3 the cursor advances past the event; `DeadLetterHandler` defaults to
   `InMemoryDeadLetterHandler`. A consumer that must lose nothing needs a configured
   `deadLetterStream` — worth a loud line in the streaming reference. (Also: `List<T>` batch
   consumers currently receive singleton batches — `StreamConsumerManager.java:459-461`.)
5. **Known and already filed, recorded here for completeness:** management-API stream publish
   path hardwires partition 0 (#524); #535's repair history (rule-1-only assignment delivered
   nothing at default replication) explains why the book teaches the two-rule assignee.

## Book-side (found and fixed this session)

6. **Module D taught a dead API shape.** Lambda mutators (`update(key, state -> ...)`) — the
   runtime takes named `Mutator` commands via a sealed hierarchy; lambdas cannot compile against
   it. Also the config example was wrong end to end: `[orders-entity]` with
   `partitions`/`replication-factor`/`terminal-ttl` vs the shipped `[entities.<keyspace>]` with
   `keyspace`/`partition_count`/`replication_factor` (all required; no `terminal-ttl` key
   exists). Both rewritten; `terminal-ttl` (open decision S2) re-marked as facade design.
7. **Module D's honesty passages had inverted.** July's corrections ("not injectable, neither HA
   nor restart-durable") became overclaims in the other direction after #596/#352/#634 — the
   entity is injectable, replicated, fsync-before-ack, crash-gated. Rewritten to per-property
   guarantees with the two open bounds (#351 timers, #349 cold restart).
8. **root.md's Part III module lettering was stale** (old five-module scheme vs the manuscript's
   A–F). Fixed.
