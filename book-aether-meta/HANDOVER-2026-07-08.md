### 3. The `Promise<Result<T>>` antipattern — caught by Sergiy, fixed everywhere

Spec v0.2 had moved ALL async APIs to `Promise<Result<T>>` (23 sites) with a changelog rationale
claiming bare `Promise` "hides the error channel". **That premise is wrong**: `Promise<T>` IS the
async `Result` — it carries typed `Cause` on its own error channel. I propagated 21 occurrences
into the book before Sergiy caught it. Both fixed: book collapsed to `Promise<T>`; spec corrected
as **v0.2.1** (committed `fa49bbd9a` in pragmatica). Sync fallible parses still return `Result`
(`validOrder`, `StateMachineDefinition.build()`) — that is correct and unchanged.

### 4. S3 resolved by Sergiy: mandatory per-step `RerunPolicy`

Neither opt-in nor opt-out. `SagaStep(name, forward, compensation, rerun)` with
`enum RerunPolicy { RUN_ONCE, IDEMPOTENT }` — **required argument, no default**; a step cannot be
declared without stating re-run safety. Rationale (recorded in spec §14 S3 + v0.2.2 changelog):
failure asymmetry — forgotten opt-in double-charges in production; forgotten opt-out costs one
fenced write; no default makes the dangerous case a compile error. Propagated to book (ORDER_SAGA
shows IDEMPOTENT/RUN_ONCE/RUN_ONCE with per-line reasons) and spec.

## Pinned idiom facts (verify-once, reuse)

- **`Promise<T>`, never `Promise<Result<T>>`** for async APIs. Sync fallible -> `Result<T>`.
- **`Fn1<R, T1>` / `Fn2<R, T1, T2>` are return-type-first** (`Functions.java:29,60`):
  forward is `Fn1<Promise<R>, C>`, compensation `Fn2<Promise<Unit>, C, R>`.
- **Guarantee vocabulary:** effectively-once (not exactly-once); bounded-stale vs linearizable
  per operation + mechanism; HA vs restart-durable; at-most-once *invocation* for `RUN_ONCE`.
- **Voice:** no em-dashes in prose (` — ` in module headings is house style); no strawman
  contrast; framework names factual (Temporal/Restate credited); orders spine only, other
  domains in vignettes; every rule carries a "why".
- `jbct-realworld` pins pragmatica 0.9.10 / aether 0.7.4 — **shapes only**, never signatures.
