## PFD 2.5.0 — the endogeneity fix

The handover before this one identified the `foundations.md` overclaim: the book said
version-control history *"does not lie"* about how a system changes. **It was in three files, not
one** — both appendices restated it, and fixing only the chapter would have left the desk
references teaching the retracted claim. The book's own convention from 2.4.0 ("the desk references
do not teach the gap") settled that.

Co-change is partly endogenous: files change together partly *because the current decomposition
forces them to*. Two adjustments keep the instrument sharp — measure co-change that **crosses a
boundary**, and trust coupling that **survives a known restructure**.

The second fix turned out larger than predicted. The prior handover assumed the Closing's scope
band already excluded the exceptions. It excludes game engines, hard real-time, embedded, numerical
pipelines — but **trust boundaries and cross-cutting concerns live inside the band**, so they were
genuinely unnamed. That made it a content addition, not a pointer.

Two `book-pfd-meta/*-DRAFT.md` files still carried the retracted claim and were fixed after you
asked; one also inherited the Tornhill lineage error.

## JBCT 4.6.0 — four facts live at the composition

The substantive research of the session, and the method matters as much as the result.

**The rule.** At a composition, test the success path, the validation failure, **each** I/O failure
separately, and **each** absorbed failure. Everything else belongs at the leaf.

**Derived, not argued.** Seven use cases read end to end across three codebases — `jbct-loan`
(DisburseLoan, EvaluateCredit, ProcessRepayment, ProcessLoanApplication), `ticketing` (AcquireHold,
BuyTicket), `jbct-realworld` (LoanOrchestrator). Five satisfy the rule; two fail it. A rule that
passed everything would have been worthless.

**What it rules out, which is half its value.** Testing that a failure at step four stops step five
tests `flatMap`, established once by the library. The *content* of a step's failure belongs to the
rule producing it. Measured against real suites, one-failure-test-per-step would have produced
roughly twice as many tests as anyone wanted.

**The generator idea died here.** A structural derivation emits tests that cannot be written (a
step typed `Promise<T>` returning `Promise.success(...)` unconditionally), tests duplicating leaf
tests, and at least one *inverted* assertion — `BuyTicket.execute_factPublishFails_stillReturns
CommittedBooking` is a failure that must **not** propagate, so "fallible step ⇒ use case fails"
generates the opposite of correct. The output of any such tool is a **gap list**, never code.

## The recovery triple was missing from every AI tool

The book has a full section — `null-policy-recovery.md:430`, `## The Recovery Triple: BER, FER,
Design-Out`, with the instruction *"name the triple for each step that changes state."*

`ai-tools/` had **zero** occurrences of `Recovery Triple`, `BER`, `FER`, `design-out`, or
`compensate`. `.recover(` appeared only as an API example. An agent writing JBCT code had no prompt
to state a guarantee, and the reviewer had no rule to catch its absence.

Fixed as a **sync block** (`recovery-triple`, joining `zone-verbs` and `predicate-naming`), not a
hand copy — hand-copying would have recreated the exact drift removed twice this session. Reviewer
gained `### Recovery Checks`; coder gained item 6, deliberately mirroring the inverse-pair rule's
shape (*a stated justification is a complete answer; silence is not*), with a guard against adding
retries or outboxes nobody asked for to dodge writing the sentence.

## Mistakes — read this part

**1. I deleted the 4.4.0 changelog entry and shipped it.** Using `## [4.4.0] - 2026-08-05` as an
Edit anchor without re-emitting it merged an entire release's notes into 4.5.0's entry. `build-pdf.sh`
renders `CHANGELOG.md` as the Revision History appendix, so the corruption reached the PDF and EPUB
on Leanpub **in the files readers had just been emailed about**. Restored, verified byte-identical
against `705c1bc`, rebuilt and republished without a second email.

Every check passed on the corrupted file: version stamp read 4.5.0, build succeeded, all four
checkers green. I verified the entry I *wrote*, never the file I *changed*. The habit that
prevents it is mechanical, not principled: **when an edit's anchor is a structural marker, diff the
file against its last-good state.** I did exactly that before committing 4.6.0 and it was clean.

**2. I called a correct design a bug, then had to retract.** Told the two counter-cases were
probably bugs, I read `publishSold`'s body with `awk` from the method signature — which strips the
preceding comment block — and concluded it swallowed a failure carelessly. The justification was
fifteen lines above: an `FER` tag naming the guarantee, the mechanism, and the cost, following the
book's own recovery-triple instruction. `buildLoanAndSchedule` **was** a bug; `publishSold` was not.

The sketched lint rule that came out of the wrong reading would have fired on all ten justified
absorbing sites in `ticketing`. Rewritten to flag *absorption lacking a justification*, which fires
on none of them.

**3. Grep proxies produced confident wrong numbers, twice in one turn.** `.flatMap(` counted as
chain steps gave "29 steps in ProcessLoanApplication" — really ~10 methods in a 586-line file — and
inflated aggregate obligation counts I then reported in a table. Withdrawn. Answering a structural
question with a text search is the same error as reading a summary instead of the source.

**4. A delegated agent burned 6+ hours for zero output.** The census brief bundled a parser, a
three-corpus census, and a judgment framework into one task; it stalled on the unbounded part
(writing the derivation script) having completed only "explore layouts". Killed, no output, no
damage — verified no writes to any corpus. The hand-read sample that replaced it produced the
finding in an afternoon. **Scope a delegated task to something that cannot stall.**

**5. Wrong build-script interface.** Passed `--final` to `book/build-pdf.sh` assuming PFD's
interface; JBCT's argument is an output name, so it reached `rm` and aborted, leaving two stray
`--final*.pdf` files. Rebuilt correctly and removed them.

## Conventions confirmed

- **Diff the file, not the edit.** When an Edit's anchor is a structural marker (a version header, a
  section heading), verify the whole file against its last-good state. Checking that your new text
  reads well is not the same claim.
- **Read what is attached to the code, not just the code.** `awk` from a signature strips the
  comment block that justifies the method. Extraction method is part of the evidence.
- **A grep counts tokens; a structure needs reading.** Do not answer a structural question with a
  text search and then report the number.
- **Scope a delegated task so it cannot stall.** A parser plus a census plus a judgment framework is
  three tasks. The bounded hand-read beat the unbounded agent by hours.
- **Absorption is not the defect; unjustified absorption is.** A rule that fires on every `.recover`
  fires on ten correct sites in one corpus alone.
- **The book leads, tooling follows.** The rule went into 4.6.0 before any lint rule exists,
  because building first would let the tool define what the book documents.
- **Book-owned content reaches the skill through a sync block**, never a hand copy. Two separate
  drift incidents this session both traced to hand copies.
- **Publishing is not notifying, and neither is proven by an HTTP 200.** Baseline
  `last_published_at`, then compare; confirm email by `EmailReadersJob` in `job_status.json`.
